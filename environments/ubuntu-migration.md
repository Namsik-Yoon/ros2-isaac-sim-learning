# Ubuntu 24.04 이전 검토

상태: 2026-11-13 사용자가 현재 PC의 Ubuntu 이전을 검토할 수 있다고 답했다. 실제 업그레이드·재설치·재부팅을 승인하거나 실행한 상태는 아니다.

목적은 Isaac Sim 주행 환경의 지원 OS를 마련하는 것이다. ROS 기초 수업은 이미 준비한 Docker 환경에서 진행할 수 있다.

## 현재 확인한 조건

- 현재 호스트는 Ubuntu 20.04 x86_64다.
- 시스템 NVMe와 `/mnt` 데이터 디스크는 서로 다른 장치다. `/mnt`는 이미 기존 파일이 들어 있는 ext4 파티션이다.
- Docker와 기존 개발 환경이 사용 중이다. 다른 프로젝트의 정확한 데이터·서비스 의존성은 아직 조사하지 않았다.
- 저장 공간은 작업 중 바뀔 수 있다. 최신 개인 `.learning/environment.json`과 실제 진단 결과를 사용한다.

## 선택 가능한 경로

| 경로 | 특징 | 먼저 확인할 것 |
| --- | --- | --- |
| 현재 OS를 순차 업그레이드 | 기존 설정을 가져가되 두 단계의 변경 영향이 있다 | 20.04 → 22.04 → 24.04 각 단계의 패키지·드라이버·부팅 확인 |
| 백업 후 24.04 새 설치 | 환경을 새로 구성하고 필요한 자료를 복원한다 | 대상 디스크, 복원 가능한 백업, 필수 프로그램 목록 |

LTS를 건너뛰는 직접 업그레이드를 계획하지 않는다. 현재 목표는 Isaac Sim과 Jazzy 조합에 맞는 24.04이며, 설치 도구가 더 최신 버전을 제시하더라도 목표 버전을 먼저 확인한다. [Ubuntu 공식 업그레이드 안내](https://ubuntu.com/server/docs/how-to/software/upgrade-your-release/), [Desktop 안내](https://ubuntu.com/desktop/docs/en/latest/how-to/upgrade-ubuntu-desktop/)

## 실제 변경 전에 준비할 결과물

1. 유지해야 할 프로젝트·데이터·서비스 목록과 중단 가능한 시간을 정한다.
2. 백업 위치와 범위를 정하고, 일부 파일을 실제로 복원해 확인한다. 이 저장소의 Git 제외 `.learning/`도 포함한다.
3. Docker의 필요한 named volume·bind mount·구성 파일과 데이터베이스 백업 방식을 확인한다. 실행 중인 DB 파일을 복사한 것만으로 복원 가능하다고 판단하지 않는다.
4. GPU 드라이버, Docker, Python 환경, 부팅·네트워크 복구 방법과 설치 USB를 준비한다.
5. 대상 디스크와 방법, 예상 중단, 되돌릴 방법을 사용자가 검토한 뒤 실제 변경을 시작한다.

이 문서는 이전 계획이다. 자동 업그레이드 스크립트나 파티션 변경 명령은 포함하지 않는다. `/mnt`의 여유 공간은 기존 데이터 삭제나 포맷 허가가 아니다.

## 이전 후 확인

OS 24.04 부팅 → 기존 자료·필수 서비스 → NVIDIA 드라이버·Docker → 이 저장소 ROS 통신 → Isaac Compatibility Checker → 작은 장면 → ROS Bridge 주행 순서로 확인한다. 검증 전에는 설치 완료나 이전 성공으로 기록하지 않는다.
