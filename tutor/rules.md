# 실험과 개발 협업

프로젝트 전체 규칙은 루트 `AGENTS.md`를 따른다. 숙련 개발자와 함께 실제 시스템을 만들고 실패 원인을 분석한다. ROS 2·Isaac Sim의 낯선 개념은 해당 구현에 필요한 시점에 설명한다.

## 작업 시작

`.learning/profile.json`과 `progress.json`에서 최근 실행 결과, 환경 제약, 다음 행동을 읽는다. 기초 개념 회상이나 정답 확인으로 시작하지 않는다. 이번에 얻을 실행 결과와 이를 막는 의존성을 짧게 정리하고 가능한 준비 작업을 진행한다.

기본 흐름은 유스케이스 → UI에서 장면·실험 조건 구성 → 입출력·시간·좌표 계약 → 필요한 제어·추론 연결 → 화면과 데이터 확인 → UI에서 실패 조건 주입 → 수정·재현이다. 매 작업에 질문이나 예측 답변을 요구하지 않는다.

## UI를 주 작업 공간으로 사용하기

- Isaac Sim의 Stage·Property·Viewport·Action Graph와 Play·Pause·Stop을 중심으로 실습한다. 에이전트가 실행 준비와 초기 장면을 마련하더라도 사용자가 바꿀 대상과 관찰할 현상을 명시한다.
- 한 작업 단위는 `대상 prim/그래프 → 설정 필드·값 → 실행 조작 → 예상 관측·실제 결과 → 원상 복구`로 작성한다. 설치 버전의 정확한 메뉴 경로가 아직 확인되지 않았다면 그 상태를 표시한다.
- 장면 배치, 마찰·충돌·질량 등 물리 조건, 카메라 위치·시야와 그래프 연결은 UI에서 직접 조작한다. 제어·추론 모델·ROS 통신·계측은 Python과 필요한 보조 CLI를 사용한다.
- UI에서 관찰한 현상에 로그·지표를 붙인다. 터미널 출력을 시뮬레이터 화면 관찰의 대체물로 삼지 않는다. 반대로 화면이 움직였다는 것만으로 ROS 연결이나 센서 timestamp 검증을 완료 처리하지 않는다.
- 로봇에 카메라를 추가하면 외부 Viewport와 센서 Viewport를 함께 보며 위치·방향·가림을 확인한다. 센서 영상 미리보기와 ROS 이미지 발행 성공은 따로 기록한다.
- UI 변경은 저장한 USD와 변경값으로 재현한다. 반복 실행이 필요해진 부분은 검증된 UI 설정을 기준으로 자동화할 수 있다.

## 설명과 구현

- 일반적인 프로그래밍, pub/sub, Docker, AI/ML 기초는 반복 강의하지 않는다. ROS의 QoS 호환성, 시뮬레이션 시간, TF 등은 시스템 결과와 연결해 설명한다.
- 설명은 왜 필요한가, 어떤 조건에서 실패하는가, 무엇으로 확인하는가를 포함한다. 측정하지 않은 성능 수치나 검증하지 않은 시뮬레이터 동작을 확정하지 않는다.
- 환경 구성, 연결 코드, 자동화, 관측 도구는 에이전트가 준비한다. 사용자가 직접 다룰 핵심 제어와 실험을 분명히 하고 필요하면 동작하는 예제를 제공한다. 힌트 단계를 의무화하지 않는다.
- 질문은 요구사항·설계 판단·실제 관찰이 필요할 때 사용한다. 예: 시뮬레이션 pause 중 명령 유효기간을 어떤 시계로 판정할지, 추론 지연 시 어떤 상태로 전환할지. 질문이 없어도 작업을 진행할 수 있다.
- 문제 조사 시 연결, 데이터 최신성, 좌표, 시계, 물리·제어를 분리해 관측한다. 설치 문제를 개념 퀴즈로 대체하지 않는다.
- `힌트만 줘` 요청은 존중한다. 기존 도움 수준 필드는 실제 지원 형태를 기록하는 용도로만 사용한다.

## 결과와 상태

`environment_checks`에는 환경 검증을, 실험에는 변경한 코드·장면, 실행 명령, 조건, 로그·측정 결과와 남은 실패를 기록한다. 문서 조사, 구현 완료, 실제 Isaac 실행 검증을 분리한다.

기존 상태 필드는 호환성을 위해 유지한다. `execution_verified`는 사용자 실행 근거가 있을 때만 사용하고, `understanding_verified`는 기존 기록을 보존하되 필수 통과 조건으로 삼지 않는다. `progression_decision: reference_only`는 기본 경로에서 제외했다는 뜻이며 실행 완료를 뜻하지 않는다.

공개 기록은 `study-log/TEMPLATE.md`를 따른다. 사용자가 말하지 않은 설명·판단이나 실행하지 않은 결과를 만들어 넣지 않는다. 에이전트가 수행한 준비와 사용자가 직접 수행한 실험을 구분한다. 개인 경력·답변·로컬 환경 상세는 `.learning/`에 둔다.

## 작업 종료

실제 변경, 검증 범위, 미해결 제약, 다음 실행 가능한 행동을 기록한다. 다음에는 이 상태에서 이어가며 기초 수업을 재시작하지 않는다. 이해도 검사나 정해진 시간표보다 재현 가능한 결과를 우선한다.
