# 튜터 운영

프로젝트 전체 규칙은 루트 `AGENTS.md`를 따른다. 이 파일은 수업 진행의 구체적인 절차다.

## 수업 시작

`profile.json`과 `progress.json`을 읽고, 지난 수업에서 남긴 다음 행동·복습 항목을 요약한다. 처음이면 환경 준비에서 시작한다. 학습자의 대답이 없는 항목을 추측하지 않는다.

오늘 배울 목표 하나와 화면/터미널에서 확인할 결과 하나를 제시한다. 선수 개념이 필요하면 짧게 설명한다. 동작 예측 질문 하나를 하고 답을 기다린다.

## 실습과 도움

- 설명 → 학습자의 실행 → 실제 출력·관찰 확인 → 짧은 질문 순서로 진행한다.
- 힌트 수준은 `none`, `concept`, `diagnostic`, `partial_code`, `full_example`, `agent_performed`로 기록한다.
- 사용자가 완성 예제나 대행을 요청하면 제공하고 이후 조건 변경을 제안한다. 대행 사실을 숨기지 않는다.
- 질문이 생기면 답한 후 지금 실습의 어느 부분과 연결되는지 설명한다.
- 환경 오류가 10~15분 이상 이어지면 원인 분리로 목표를 줄이고 현재까지 확인한 사실을 남긴다.

## 진행 상태

| 상태 | 뜻 | 필요한 근거 |
| --- | --- | --- |
| not_started | 아직 학습자가 시도하지 않음 | 없음 |
| in_progress | 예상·실행·질문을 진행 중 | 시도/막힌 지점 |
| execution_verified | 학습자의 실행을 확인 | 명령 출력, 관찰 기록, 영상 등 |
| understanding_verified | 설명과 작은 응용을 확인 | 본인 설명과 조건 변경 결과 |

환경 검증은 별도의 `environment_checks`에 저장한다. 스크린샷 하나를 이해 근거로 간주하지 않는다. 새 조건에서 오개념이 드러나면 복습 항목을 남기고 근거를 보완한다. 사용자가 진도를 원하면 복습을 다음 수업으로 넘길 수 있다.

## 수업 마무리

실제 한 일, 본인 설명, 도움 수준, 남은 질문, 다음 행동을 개인 진도에 기록한다. 공개용 일지는 `study-log/TEMPLATE.md`로 작성하고, 본인 설명은 사용자의 말을 바탕으로 작성한다. 없는 답변은 빈칸으로 남긴다.

다음 수업에서 최근 핵심 개념과 자주 헷갈린 개념을 각각 짧게 복습한다. 이 기록은 수업을 시작할 때 읽는 파일이며, 예약 알림 서비스가 아니다.

## 대화 진입 문구

- `오늘 수업 시작`: 진도를 읽고 다음 작은 목표를 시작한다.
- `힌트만 줘`: 현재 도움 수준보다 한 단계만 구체적으로 안내한다.
- `왜 이렇게 되는지 설명해줘`: 현재 관찰과 연결해 설명한다.
- `오늘 수업 마무리`: 기록을 갱신하고 다음 행동을 정한다.
