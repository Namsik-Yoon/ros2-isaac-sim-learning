# NNN — 시스템에서 확인할 결과

상태: 설계 / 구현 / 실제 시뮬레이터 검증 중 해당 범위를 적습니다. 예상 작업 단위는 60분이며 환경 설치 시간은 별도로 기록합니다.

## 유스케이스와 실패 조건

무엇을 가능하게 하는지, 실제 운용에서 어떤 조건에 실패할 수 있는지 적습니다.

## 준비 상태와 계약

- 필요한 환경·장면·파일과 실제 검증 여부
- 입출력 토픽·메시지·QoS·주기
- 좌표계·단위·시간 기준·데이터 최신성
- 에이전트가 준비할 부분과 사용자가 직접 구현·변경할 부분

## 실행과 측정

최소 재현 명령, 화면·로그·지표, 기준 실행을 적습니다. 실행 위치를 표시하고 ROS 고유의 개념은 해당 계약에 필요한 만큼 설명합니다. 구현 전 예제와 실제 실행된 결과를 구분합니다.

## 실패 주입과 수정

한 번에 조건 하나를 바꿉니다. 증상, 관측 지표, 원인 후보, 수정 전후 비교를 적습니다. 정지·복구·초기화 절차도 포함합니다.

## 완료 기준

- [ ] 명시한 조건에서 실제 실행 결과를 남겼다.
- [ ] 지표의 정의·시간 기준·측정 한계를 기록했다.
- [ ] 실패를 재현하고 수정 결과 또는 남은 문제를 기록했다.
- [ ] 다른 사람이 같은 조건으로 실행할 수 있다.

에이전트와 사용자의 실행 주체를 구분합니다. 이해 확인 질문은 필수가 아닙니다. 설계 결정이 필요한 경우 선택지와 영향을 적습니다.

## 기록·출처·다음 행동

공식 문서와 버전, 실제 결과, 남은 제약과 다음 실행 가능한 작업을 기록합니다.
